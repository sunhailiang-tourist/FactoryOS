## 2. 产品概述

### 2.1 产品定位

**Ax OS = 制造业智能中枢 Overlay**

在客户 ERP/MES 账本之上，提供 **敢写、可追、可回滚** 的 AI 执行能力。

| 是 | 不是 |
|----|------|
| ERP/MES 之上的执行 Overlay | ERP 替代品 |
| 冻结链路 + 规则 + 审计 + 撤回 | 无治理聊天机器人 |
| 第一家部署可导出、第二家可导入 | 装完离场 |

**品牌语**：智能中枢系统 · AI 时代 · 全域连接 · 全程可追

### 2.2 产品目标

| 目标 | 度量 |
|------|------|
| 第一家工厂 D1 可结案 | 五机制 + 报工 + Package 导出 |
| 实施无需改代码仓库 | Studio 完成配置 |
| 工人愿意用 | 报工 P50 ≤30s |
| 企业敢开写 | Shadow≥14d + 双签 + 零未解释 drift |
| 第二家可复制 | Import ≤3 周（Silver） |

### 2.3 产品形态

两个应用、一个内核：

```text
web-admin（Ax OS）  ─┐
                     ├── os_core 内核 ──► 客户 ERP/MES
h5-worker（产线 H5） ─┘
```

## 4. 产品架构

### 4.1 功能架构图

```text
Ax OS
├── 制造全景（看）
│   ├── 首页概览
│   └── 工单/异常看板
├── 产业连接（接）★ Studio
│   ├── 租户管理
│   ├── ① Connect 连通
│   ├── ② Discover 发现
│   ├── ③ Map 映射
│   ├── ④ Prove 验证
│   ├── ⑤ Freeze 冻结
│   └── ⑥ Export 导出
├── 资产与复制（复制）
│   └── Package 导入
├── 运营与合规（管）
│   ├── Shadow / 开写批准
│   ├── 对账 Drift
│   ├── 审计时间线
│   └── 运维事件
└── 平台治理（SaaS）
    ├── 租户
    └── License / Pack

h5-worker（产线）
├── 当前工单
├── 报工（语音/扫码/拍照/手动）
├── 确认提交
└── 主管待办确认
```

### 4.2 内核能力架构（业务视角）

```text
感知输入 → Agent 计划 → Harness 确认 → Rule 授权 → Execution 执行 → Connector 写 ERP
                ↑              ↑              ↑
           graph 须冻结    默认拒绝      唯一写路径
                └──────── audit 全程记录 ────────┘
```

### 4.3 os_core 模块与产品能力映射

| 模块 | 产品能力 | 用户感知 |
|------|----------|----------|
| graph_service | 业务链路定版 | 未冻结不能生产写 |
| rule_engine | 操作授权 | 无权提示 |
| execution_service | 受控执行 | 成功/模拟/失败/已撤回 |
| audit_service | 责任追溯 | 审计记录 |
| connector_sdk | 系统连接 | 在线/熔断 |
| agent_orchestrator | 听懂意图 | 计划卡 |
| license_service | 模块授权 | 未购不可用 |
| platform_registry | 配置管理 | Studio 全部配置 |
| mcp_gateway | 外部工具入口 | 走同一写路径 |

## 5. 业务流程

### 5.1 主流程总览

```text
                    ┌─────────────┐
                    │  UC-01 接入  │
                    └──────┬──────┘
                           ▼
              Connect → Discover → Map
                           ▼
              Prove(Shadow+双签) → Freeze → Export
                           ▼
                    ┌─────────────┐
                    │ UC-02 报工  │◄──── 日常循环
                    └──────┬──────┘
                           ▼
                    对账 · 审计 · 运维
                           ▼
                    ┌─────────────┐
                    │ UC-03 复制  │
                    └─────────────┘
```

### 5.2 流程一：首家工厂接入（UC-01）

**前置**：准入评估通过，Path A/B/C 已裁定

| 步骤 | 业务动作 | 责任方 | 产出 |
|------|----------|--------|------|
| 1 | 测试连通 Legacy | 实施+客户IT | 连通报告 |
| 2 | 发现标准动词 CMV | 实施 | 动词清单 |
| 3 | 字段映射确认 | 实施 | 映射表 |
| 4 | Shadow≥14d + 对账 + 双签 | admin+业务负责人 | 开写批准 |
| 5 | Graph 冻结签字 | 业务负责人 | frozen Graph |
| 6 | 导出 Package | 实施 | Package JSON |

**关键规则**：
- Connect 阶段禁止任何写
- Prove 未双签禁止生产写
- 配置只经 Studio 发布，不改 Git YAML

### 5.3 流程二：日常报工（UC-02）

| 步骤 | 动作 | 系统行为 |
|------|------|----------|
| 1 | 工人说/扫/拍 | 生成计划卡（未执行） |
| 2 | 工人确认 | Harness 第一扇门 |
| 3 | 主管 IM 待办确认 | Harness 第二扇门 |
| 4 | Rule 通过 | 允许执行 |
| 5 | Execution 写 ERP | 产生 ExecutionRecord |
| 6 | 次日对账 | ok 或 drift 告警 |

**撤回**：主管 24h 内可撤回，须填原因。

### 5.4 流程三：第二家导入（UC-03）

```text
Import Package → 更新凭证/URL → 差异确认 → Prove + 双签 → 上线
（治理步骤不可跳过）
```

### 5.5 写入路径（Path）

| Path | 客户 | 写目标 |
|------|------|--------|
| A | 有 ERP 无 MES | ERP |
| B | 有 MES | MES |
| C | 无 ERP | 内置账本 |

## 9. 业务规则

### 9.1 全局规则

| 编号 | 规则 |
|------|------|
| BR-01 | 所有 L2 写必须 Graph frozen |
| BR-02 | Rule 默认拒绝 |
| BR-03 | Agent 只出计划，不执行写 |
| BR-04 | 生产写须 write_approved |
| BR-05 | 新租户默认 shadow_mode=true |
| BR-06 | L2 写须 idempotency_key |
| BR-07 | 配置发布只经 Studio API |

### 9.2 Graph 状态

```text
draft → in_review → frozen → deprecated
```

| 状态 | 可 L2 写 |
|------|----------|
| frozen | ✅ |
| 其他 | ❌ |

### 9.3 人审 Gate（不可跳过）

| Gate | 页面 | 签署人 |
|------|------|--------|
| 开写批准 | W-07 | admin + business_owner |
| Graph 冻结 | W-08 | business_owner |
| UAT | 线下 | business_owner |
