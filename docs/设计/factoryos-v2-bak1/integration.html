Prove 阶段需实施方 + 客户方双签确认。在 Shadow Mode 验证通过、对账一致性达标后方可开启生产写权限。

Studio 与 MCP 关系

Studio 负责静态 Blueprint 配置与映射；MCP Gateway 负责运行时动态转换。MCP Y1 末内部 GA，Y2 逐步对外开放。

数据回灌策略

支持将历史 Execution Evidence 反向回灌至 Data Lake (L3)，用于流程优化建议。

STU 铁律自检

STU-R1: 配置只经 Studio 发布

租户 `tenant_profiles`、`system_relations`、`connector_instances`、`override_documents` 的 **published 写入** 仅经 Studio UI → `/v1/registry/*` 或 `/v1/integration/*`。违反则不算 D1 交付完成。

STU-R2: 无需改仓库 onboard

实施顾问/客户 IT **无需** clone 仓库、改 YAML、提 PR。配置变更全在 Studio 内完成，Studio 自动同步到 DB。

STU-R3: Connector 仅通过 MCP Gateway 调用

禁止直连 Legacy 系统。所有 Connector 调用必须经过 MCP Gateway 路由，确保审计与鉴权统一。

STU-R4: CLI 仅调试，禁止 CLI publish

CLI 仅用于本地开发调试，所有配置发布必须通过 Studio UI。禁止 CLI 直接调用 `/v1/registry/*` 发布接口。

STU-R5: OverrideDocument 经 Studio publish 生效

禁止手改 Pack JSON 或 Git YAML 覆盖配置。OverrideDocument 必须通过 Studio 编辑、审核、发布后生效。
