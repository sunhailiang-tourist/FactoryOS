写入路径与部署隔离模型 (Path & Deployment)

子区块1：三条写入路径 (Path A/B/C)

路径 定义 写入方式 典型场景
Path A ERP 写路径 Agent → DSL → Rule Engine → Connector → ERP API 直接写入 哈森灯塔：无MES，报工直写金蝶ERP
Path B MES 写 + ERP 读 MES 负责写入生产数据，Connector 读取 ERP 数据用于对账/追溯 通用MES厂：MES写入+ERP读取 (Acme占位, 当前blocked)
Path C Builtin 内置账本 Agent → DSL → Rule Engine → builtin_ledger schema (PostgreSQL) B-Lite：无ERP无MES环境，内置账本实现D1报工闭环

子区块2：三种部署隔离模型 (Pool/Bridge/Silo)

模型 描述 适用场景
Pool SaaS多租户池，单VPC·RDS·tenant_id+RLS逻辑隔离 哈森灯塔（首期SaaS部署）
Bridge schema-per-tenant 隔离，同库不同schema，非私网桥接 通用MES厂（需要schema级隔离）
Silo 独立部署，内置账本独立运行 B-Lite（无ERP无MES）
说明文字：写入路径（Path A/B/C）与部署模型（Pool/Bridge/Silo）是两个独立维度。例如 Path A 可以跑在 Pool 上也跑在 Silo 上；Path C 可以选择 Silo 也可以选择 Pool。当前首期哈森灯塔采用 Path A + Pool 组合。

唯一写路径红线 (The Red Line)

MANDATORY ExecutionEvidence 必须在 Connector 调用前持久化
  • 禁止 Agent 直接写数据库
  • 禁止无确认的库存调整/自动审批
  • 先读 → 后建议 → 再确认 → 最后自动化
