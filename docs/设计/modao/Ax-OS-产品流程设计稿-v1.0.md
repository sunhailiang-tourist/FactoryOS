# 篇章一 · 产品业务思路

## P01 · 产品定位一页纸

### 我们是什么

**Ax OS = 制造业智能中枢 Overlay**

在客户 **ERP/MES 账本（Data-L0）** 之上，提供 **敢写、可追、可回滚** 的 AI 执行层。

### 我们不是什么

- ❌ ERP 替代品
- ❌ 无治理的聊天机器人 / Agent 直连数据库
- ❌ 客户全量业务数据中台（默认不做）

### 核心价值（行业语言）

| 成果 | 含义 |
|------|------|
| 打破孤岛 | 多系统经中枢编排，账本仍在客户系统 |
| 执行可管 | 冻结链路 + 规则门禁 + 人工确认 |
| 决策可追 | 审计 + 对账 + 可撤回 |
| AI 降复杂度 | 说/扫/拍代替菜单，不是代替财务账本 |

### 产品双极（必须同时成立）

```text
┌─────────────────────┐       ┌─────────────────────┐
│  终端极 · 体验       │       │  内核极 · 信任       │
│  工人愿意用          │       │  企业敢让写          │
│  说/扫/拍 · ≤3点击   │       │  Graph冻结·Rule·Audit│
└──────────┬──────────┘       └──────────┬──────────┘
           └──────── Harness 确认门 ────────┘
```

## P02 · 客户分型与切入策略

| 类型 | 特征 | 策略 | 产品形态 |
|------|------|------|----------|
| **A 类** | 有 ERP/MES | **优先做** | Overlay · Path A 或 B |
| **B 类** | 系统乱 + Excel | 痛点强、接入难 | 先只读/半自动 |
| **C 类** | 无 ERP | **暂缓** | 远期 Product B / B-Lite |

**Phase 1 场景顺序**：报工 → 生产分析 → 管理决策（先读后写）

**Phase 1 禁止**：自动财务过账、付款、库存调整、未确认自动审批

**运营铁律**：读 → 建议 → 确认 → 自动化

## P03 · 两次交付模型（D1 / D2）

```text
┌─────────────────────────────────────────────────────────┐
│  D1 · 通病包（≤90天书面结案）                              │
│  五项机制：只读查询 · 受控写 · 全审计 · 可撤回 · 每日对账      │
│  + 垂直场景：生产报工（work_report_v1）                     │
│  产出：Implementation Package v1                          │
└────────────────────────┬────────────────────────────────┘
                         │ 工厂特异需求
                         ▼
┌─────────────────────────────────────────────────────────┐
│  D2 · 扩展包                                              │
│  计件、质量追溯、外协等 · ≥70% 必须 Pack 化入库              │
│  产出：Package v2                                         │
└─────────────────────────────────────────────────────────┘
```

| 对比 | D1 | D2 |
|------|-----|-----|
| 周期（首家） | 6–9 月（含探路） | D1 后 4–10 周 |
| 第二家同模板 | 4–8 周 或 Silver import 2–3 周 | 扩展项另议 |
| 结案标准 | Shadow≥14d + UAT + 导出 Package | 新 Graph 冻结 + D1 回归 |

### 模块 → 业务语言对照

| 模块 | 业务上解决什么 | 用户可感知 |
|------|---------------|-----------|
| graph_service | 业务流程「定版」 | 未冻结不能生产写 |
| rule_engine | 谁能在什么条件下做什么 | 无权/允许 |
| execution_service | 唯一受控写库 | 成功/模拟/失败/撤回 |
| audit_service | 责任可追溯 | 审计时间线 |
| connector_sdk | 对接客户系统 | 连通/熔断 |
| agent_orchestrator | 听懂人说的话 | 计划卡（未执行） |
| license_service | 商业化边界 | 未购模块不可用 |
| platform_registry | 配置发布真源 | Studio 全部配置 |
| mcp_gateway | 外部 AI 工具入口 | 须走同一写路径 |

## P07 · 唯一写路径（产品红线）

```text
感知/对话/扫码
      ▼
 Agent 产出【计划】（不执行）
      ▼
 Harness 人工确认（工人 + 主管）
      ▼
 Rule 评估（默认拒绝）
      ▼
 Execution（shadow 或真实）
      ▼
 Connector → 客户账本（Data-L0）
      ↕
 Audit 全程记录 · 可 Revert · 可对账
```

**产品承诺**：任何 L2 写都走这条链；Agent/MCP **不能**绕过。

---

## P08 · 三条写入路径（Path A/B/C）

| Path | 客户画像 | 写到哪里 | 读从哪里 | 灯塔 |
|------|----------|----------|----------|------|
| **A** | 有 ERP、无 MES | ERP | ERP | 哈森 |
| **B** | 有 MES | MES | ERP 只读 | 平台默认 |
| **C** | 无 ERP（B-Lite） | 内置 PG 账本 | 内置 | 选配 |

**产品原则**：L0 机制相同；差异仅在 Registry 绑定的 Pack，**不做客户硬编码**。

---

## P09 · 数据边界（卖什么数据能力）

```text
Data-L0  客户账本（ERP/MES）     ← 权威，FactoryOS 不替代
Data-L1  运行数据（必做）        ← Graph/Audit/Execution/对账
Data-L2  最小缓存（按需+TTL）     ← 能读 ERP 就不落库
Data-L3  分析数仓（选配另立项）   ← 默认不承诺
```

**对外标准话术**：部署 + 运行平台（审计、回滚、对账），**不是**托管全厂业务数据。

# 篇章三 · 业务规划流程

## P10 · 全生命周期 Gate 地图

```text
售前          接入配置              运行治理           复制
 │              │                    │               │
G-ADMIT ─► G-PATH ─► G-CONNECT ─► … ─► G-PROVE ─► G-FREEZE
                      │                    │
                      ▼                    ▼
                 G-DISCOVER          G-WRITE-APPROVE
                      │                    │
                      ▼                    ▼
                   G-MAP              G-UAT ─► G-EXPORT
                      │                                  │
                      ▼                                  ▼
              G-BRONZE-REVIEW                        G-IMPORT
                      │
                      ▼
               G-GRAPH-DRAFT ─► G-FREEZE
```

### 人审 Gate（❌ 不可自动化）

| Gate | 业务含义 | 责任方 |
|------|----------|--------|
| G-FREEZE | 业务链路定版签字 | business_owner |
| G-WRITE-APPROVE | 批准真写 Legacy | admin + business_owner |
| G-BRONZE-REVIEW | 新 Blueprint 评审 | integrator + platform |
| G-UAT | 试点验收 | business_owner |
| G-DRIFT | 对账漂移处置 | ops + integrator |

---

## P11 · Studio 六步 · 业务含义（非界面）

| 步 | 业务问题 | 产出 | 禁止 |
|----|----------|------|------|
| Connect | 能连上客户系统吗？ | 连通报告 | 此阶段任何写 |
| Discover | 厂商 API 对应哪些标准动作？ | CMV 候选 | — |
| Map | 字段对齐对吗？ | 映射表 | AI 自动 publish |
| Prove | 影子跑够久、账对吗？ | 开写批准书 | 未满 14d 开写 |
| Freeze | 报工链路定版了吗？ | frozen Graph | AI 自动冻结 |
| Export | 经验能带走吗？ | Package | 无导出=交付未完成 |

**配置真源**：Studio → API → PostgreSQL Registry（**不是**改 Git YAML 上线）

# 篇章四 · 商业化与演进

## P15 · 三层 Pack 商业化

```text
Pack-L1  Graph Pack     场景（报工、查询…）
Pack-L2  Capability Pack  能做什么（读/写/感知…）
Pack-L3  Connector Pack   连什么系统（金蝶/MES/钉钉…）
```

| 套餐 | 典型客户 | 包含 |
|------|----------|------|
| Starter-A | Path A / 哈森 | D1 五机制 + ERP 写读 + IM |
| Starter | Path B | + MES 写 |
| Starter-B-Lite | Path C | + 内置账本 |
| Pro/Enterprise | 扩展 | 分析读图 + Override + 多租户治理 |

**收入层次**：L0 平台订阅 · L1 D1 包 · L2 沉淀 Pack · L3 定制 Override

---

## P16 · 规模演进（产品阶段）

```text
Gate 0        Stage 1           Stage 2         Stage 3
内核52项绿      Studio+API         h5-worker        灯塔项目
     │              │                  │                │
     ▼              ▼                  ▼                ▼
  core-v1.0    可配置交付          终端体验          生产验证
                    │
              S0 1-10 tenant ──► S1 百级 RLS ──► S2 Cell ──► S3 Silo
```

**研发锁序**：1a API → 1b Studio → 2 终端 → 3 项目（不三线并行哈森）

## P17 · 战略演进（长期，非 Day1）

```text
Stage1  业务图谱（怎么运转）     ← D1 在做
Stage2  体验网络（怎么判断）     ← Y2+ 按角色沉淀
Stage3  决策参考（选项+引用）   ← 规划
Stage4  工厂大脑（有界自治）     ← 愿景
```

**诚实边界**：Experience Schema 尚未进 contracts；不否定终局，但 **编码真源** 仍是 Graph+Rule+Execution。
